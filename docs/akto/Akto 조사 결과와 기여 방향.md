# Akto 조사 결과와 기여 방향

조사 기준일: 2026-10-06

최한림 교수님은 처음부터 새로 만들기보다 Akto에 개선을 제안하는 방법을 먼저 검토하라고 말씀하셨다. 제안한 수정이 반영되기 어렵다면, 원본을 복사해 별도 버전으로 개발하는 방법을 검토한다.

이 방향을 판단하기 위해 관리 상태, 커뮤니티, BOLA 관련 기록, 한국 개인정보 지원, AI 기능, 개선 후보를 확인했다.

## 먼저 알아둘 결론

**Akto를 활용하고, 직접 확인한 작은 문제부터 원본에 개선을 제안하는 방향이 적절하다.**

최근까지 개발되고 있고 다른 계정의 수정이 반영된 사례도 있다. BOLA 검사와 AI 기능도 이미 제공한다.

다만 우리 수정이 빨리 받아들여진다는 보장은 없다. 아직 Akto를 실제 앱에 실행해 우리 도구와 탐지 성능을 비교한 것은 아니다.

## 1. 계속 관리되고 있나

**최근까지 활발하게 개발되고 있다.**

- 기본 브랜치의 최근 수정은 2026-10-05에 있었다.
- 같은 날 `v2.37.0` 버전이 공개됐다.
- 10월 4~5일에도 여러 버전이 공개됐다.

다만 한 저장소에 여러 구성요소의 버전이 섞여 있다. 출시 횟수만으로 본체가 일정한 주기로 나온다고 해석하지 않는다.

수정 제안의 처리 속도도 일정하지 않다.

| 사례 | 확인한 결과 |
|---|---|
| BOLA 인증 정보 교체 수정 #1359 | 제출 후 약 2분 만에 반영됐다. 빠른 처리 사례지만 모든 제안의 처리 속도를 대표하지 않는다. |
| 알림 기능 수정 #213 | 2023-03-20 제출, 03-24 반영으로 약 4일 걸렸다. |
| 로컬 설치 화면 차단 수정 #6112 | 2026-08-15 제출 후 조사일에도 열려 있으며 아직 반영되지 않았다. |

전체 이슈의 평균 응답 시간은 계산하지 않았다. 개발이 활발하다는 사실과 외부 사용자의 모든 문제를 빨리 해결한다는 주장은 구분한다.

## 2. 다른 사람의 기여를 받아들이나

**다른 계정에서 제안한 수정이 원본에 반영된 사례가 있다.**

조사일에 GitHub에서 확인한 규모는 다음과 같다.

| 항목 | 확인한 수치 |
|---|---:|
| 별 | 1,527개 |
| 저장소 복사 | 294개 |
| 기여자 목록 | 55개 계정 |

기여자 목록에는 봇도 포함된다. 현재 활동하는 사람 55명이라는 뜻은 아니다.

개인 계정의 알림 기능 수정 #213과 민감한 파일 검사 수정 #239가 반영됐다. 따라서 우리도 개선을 제안할 수 있는 통로는 있다. 다만 계정 표시만으로 작성자의 회사 소속까지 확인한 것은 아니다.

## 3. BOLA 관련 문제를 고친 기록이 있나

BOLA는 **다른 사람의 비공개 정보를 권한 없이 조회하는 문제**다. 이번 프로젝트에서는 읽기와 조회를 대상으로 한다.

**Akto에는 이미 BOLA 검사 기능과 관련 수정 기록이 있다.**

| 기록 | 쉽게 설명하면 |
|---|---|
| 본체 #1359, 2024년 8월 | 다른 사용자로 검사할 때 인증 정보가 제대로 추가되거나 교체되도록 고쳤다. |
| 본체 #1363, 2024년 8월 | 비공개 정보 관련 검사에서 프로그램이 오류로 멈추는 부분을 고쳤다. |
| 검사 규칙 #81·#85, 2024년 5월 | 오류나 계정 잠김 응답을 정보 노출로 잘못 신고하지 않도록 조건을 보완했다. |

회의에서 언급한 2023~2024년의 특정 결함 이슈가 정확히 어느 글인지는 확정하지 못했다. 위 기록은 이번 조사에서 실제로 확인한 관련 수정이다.

이 기록만으로 Akto가 지금 모든 읽기 문제를 정확히 찾는다고 결론 내리지는 않는다.

## 4. 한국 개인정보 지원에서 보완할 부분이 있나

**보완할 여지는 있지만, 한국어 기능이 전혀 없다고 표현하면 안 된다.**

- 확인한 기본 개인정보 규칙 파일에서는 한국 주민등록번호 전용 규칙을 찾지 못했다.
- 별도의 개인정보 가림 기능은 확인한 코드에서 영어를 기본으로 사용한다.
- 사용자가 원하는 탐지 규칙을 직접 추가하는 기능은 이미 있다.
- Akto가 개인정보 가림에 사용하는 Presidio라는 도구에는 한국 주민등록번호 등 한국 식별번호 규칙이 있다. 다만 규칙이 있다는 사실과 Akto에서 그 규칙이 실제로 켜져 있다는 사실은 다르다.

따라서 주민번호 규칙을 하나 추가하는 데서 끝내기보다, **기존 기능으로 한국어 응답을 어디까지 처리할 수 있는지 먼저 확인하는 것이 맞다.**

한국 전화번호를 놓치는지, 일반 주문번호를 개인정보로 잘못 찾는지, 한국어 이름이나 주소를 제대로 구분하는지 확인하면 구체적인 개선 후보를 찾을 수 있다. 이 항목들의 실제 성능을 모두 확인했다는 뜻은 아니다.

## 5. AI 기능이 있나

**이미 있다.**

- AktoGPT는 설명을 입력하면 탐지 규칙을 만드는 기능을 제공한다.
- 현재 제품은 AI 에이전트의 행동과 정보 노출을 검사하는 보안 기능도 소개한다.

다만 AI 기능이 있다는 이유만으로 읽기 권한을 정확하게 판단한다고 볼 수는 없다. 상용 제품에 소개된 기능이 공개 코드에서 모두 그대로 실행된다고 가정하지 않는다.

## 6. 무엇을 개선하고, 어떤 방식으로 개발할까

**기여를 먼저 검토한다.** 여기서 기여는 작은 수정을 만들어 Akto 원본에 반영해 달라고 제안하는 것이다.

읽기 검사에서는 다음을 개선 후보로 확인한다.

- 검사 과정에서 비공개 정보에 관한 단서가 빠지는지
- 목록에 자기 정보와 다른 사람의 비공개 정보가 섞여 있을 때 제대로 구분하는지
- 정상 공개 정보나 오류 응답을 정보 노출로 잘못 신고하는지

현재 로컬 조사에서 먼저 확인 중인 후보는 첫 번째 항목이다. 나머지 두 항목은 추가 확인 후보다. 실제 앱 전체 검사 결과를 보고 최종 수정 내용을 정한다.

한국어 개인정보 처리는 별도 개선 후보로 두고, 기존 설정으로 해결되는 부분부터 확인한다.

진행 순서는 다음과 같다.

1. 준비한 wger와 Memos 자료에 Akto를 실행한다.
2. 실제로 놓친 문제나 잘못 신고한 경우를 확인한다.
3. 확인한 문제 하나를 고치고 같은 자료로 다시 검사한다.
4. 작은 수정으로 원본에 반영할 수 있는지 검토한다.
5. 수정이 거절되거나 원본이 지원하지 않는 방향이라면, 원본을 복사해 별도 버전으로 개발한다.

**아직 확정되지 않은 것은 정확한 수정 내용과 그 효과다.** 자료 조사는 진행됐지만 Akto와 우리 도구의 전체 비교는 남아 있다.
