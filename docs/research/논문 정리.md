### 완료
1. **Sahin, Zhang, Arcuri — *Enhancing REST API Fuzzing with Access Policy Violation Checks and Injection Attacks*** (arXiv 2604.00702) · **2026년 4월** [https://arxiv.org/pdf/2604.00702](https://arxiv.org/pdf/2604.00702)<br>→ REST API 퍼징에 인가 위반 탐지 오라클을 붙인 연구. *"남의 리소스 접근=위반으로 단순화하면 오탐만 쏟아진다"*는 네 출발점.
2. **(저자 미상 표기) — *AuthProbe: Specification-Driven, Multi-Identity Detection of Broken Object-Level Authorization in Recruitment APIs*** (arXiv 2607.20574) · **2026년 7월** [https://arxiv.org/pdf/2607.20574](https://arxiv.org/pdf/2607.20574)<br>→ 두 계정의 소유권 정답으로 차분해 BOLA를 확정하는 저오탐 스캐너. **가장 가까운 경쟁자**(소유권은 알되 공개/공유 가시성은 모름 ← 네 공격점).
3. ***Broken Object Level Authorization in the Wild: An Empirical Taxonomy from 100+ Bug Bounty Disclosures*** (arXiv 2605.25865) · **2026년 5월** [https://arxiv.org/pdf/2605.25865](https://arxiv.org/pdf/2605.25865)<br>→ 버그바운티 100여 건으로 BOLA 유형을 분류한 실태 논문. 문제의 **현실성 근거** + 읽기(GET)만 다룬다는 범위 한정 근거.
4. ***A Non-Intrusive Traffic Analysis Framework for Authorization Risk Detection and Coordinated Response in Web Applications*** (arXiv 2607.16754) · **2026년 7월** [https://arxiv.org/pdf/2607.16754](https://arxiv.org/pdf/2607.16754)<br>→ 트래픽 비침습 분석으로 인가 위험을 탐지. 저자가 *"앱마다 재조정 필요 + 실험이 실환경과 다름"*을 인정 → 네 평가 정직성(보류율까지 재는 이유) 논거.

### 미완료
1. ***OpenAPI Specification Extended Security Scheme: A Method to Reduce the Prevalence of Broken Object Level Authorization*** (arXiv 2212.06606) · **2022년 12월** [https://arxiv.org/pdf/2212.06606](https://arxiv.org/pdf/2212.06606)<br>→ OpenAPI 표준엔 객체 수준 권한을 적을 자리가 없다며 명세를 확장하는 제안. *"가시성 라벨을 외부에서 주입해야 한다"*의 정당화.
2. **Liu et al. — *BACScan: Automatic Black-Box Detection of Broken-Access-Control Vulnerabilities in Web Applications*** (CCS '25) · **2025년 11월**(학회 10/13–17, 타이베이) [https://www.cse.cuhk.edu.hk/~wei/papers/ccs25-BACScan.pdf](https://www.cse.cuhk.edu.hk/~wei/papers/ccs25-BACScan.pdf)<br>(예비: [https://yuanxzhang.github.io/paper/bacscan-ccs25.pdf](https://yuanxzhang.github.io/paper/bacscan-ccs25.pdf) )<br>→ 두 세션 탐색 결과를 비교해 접근제어 버그를 찾는 블랙박스 도구. **공개 여부를 관찰로 추정**하는 대표 베이스라인(공유/로그인공개 범주·보류 없음 ← 네 차별점).

### 유료 
1. **Atlidakis, Godefroid, Polishchuk — *Checking Security Properties of Cloud Service REST APIs*** (ICST 2020) · **2020년 10월** [https://doi.org/10.1109/ICST46399.2020.00046](https://doi.org/10.1109/ICST46399.2020.00046)<br>→ 클라우드 REST API용 보안 규칙 4종 제안. *"다른 토큰으로 재요청해 성공하면 위반"* — **네가 넘어서려는 단순 규칙의 원형**.
